# L347-B Findings — S023 Offer Unlock button disconnected

**Date:** 2026-10-03
**Type:** Production bug (frontend-backend disconnect)
**Severity:** HIGH — provider cannot submit unlock request

## Bug

`resources/views/offer-unlock.blade.php::doUnlock()` only shows a toast
message. It does NOT call `POST /api/v1/offer-submissions`, even though
`OfferUnlockController@store` is fully implemented.

## Impact

- Provider clicks "Unlock Now" -> "feature being finalized" message
- No `OfferSubmission` row created
- Backend endpoint `POST /api/v1/offer-submissions` is dead code from UI perspective

## Root cause

View was written before `OfferUnlockController` was implemented.
Controller was added, view was never updated to call it.

## Fix (L347-B)

`doUnlock()` now POSTs to `/api/v1/offer-submissions` with `need_id`,
CSRF token, cookie auth. On success shows `featurePendingBody`
(payment flow not yet implemented). On error shows error message.

Removed outdated comment: "No unlock API exists yet".

## Out of scope (documented, not fixed)

1. `unlock_info` missing from `NeedController@show` -> `renderUnlock()` always shows dash
2. Payment flow after `PENDING_PAYMENT` missing -> no UI to reach `UNLOCKED`

Both require design-owner input. Tracked for future work.
