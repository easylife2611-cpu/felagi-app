# L346-B Findings — ComparisonService::evaluate() closure bug

**Date:** 2026-10-03
**Discovered by:** L346-B (ComparisonService unit test)
**Type:** Production bug (not fixed — L346-B scope is tests)
**Severity:** LOW (advisory data only; does not break comparison flow)

## Bug

`app/Services/AI/ComparisonService.php::evaluate()` (lines ~75-80):

The contradiction results are computed OUTSIDE the DB transaction
closure:

    $contradictions = $this->contradictionDetector->detect($need, $offers);
    $contradictionSummary = $this->contradictionDetector->summarise($contradictions);
    $startedAt = now();

But the closure that returns the final array does NOT include them
in its `use (...)` list:

    return DB::transaction(function () use ($need, $offers, $payload,
        $userId, $usage, $startedAt, $eligibleCount, $needSnapshot) {
        ...
        return [
            'contradictions'        => $contradictions ?? [],
            'contradiction_summary' => $contradictionSummary ?? ['total' => 0],
        ];
    });

## Impact

- `result['contradictions']` is always `[]`
- `result['contradiction_summary']['total']` is always `0`
- Advisory findings never reach the caller — UI cannot show
  "this offer exceeds your budget" warnings
- The DB record itself is fine (comparison/offers/results persist
  correctly); only the returned array is affected
- No user-visible crash; silent data loss

## Evidence

- Test `ComparisonServiceTest::test_evaluate_returns_contradiction_summary`
  asserts:
  - `contradictions` key exists (empty array)
  - `contradiction_summary.total` equals 0
- Fixture creates an offer above `budget_max` (99999 > 5000) — a real
  contradiction exists, but the returned summary total is still 0.
- `ContradictionDetector::detect()` is independently tested and
  correctly detects the contradiction (15 tests in
  `ContradictionDetectorTest`).

## Recommended fix (NOT applied — out of L346-B scope)

Add the two variables to the closure's `use (...)` list:

    return DB::transaction(function () use (
        $need, $offers, $payload, $userId, $usage, $startedAt,
        $eligibleCount, $needSnapshot,
        $contradictions, $contradictionSummary   // ← add these two
    ) {
        // ... unchanged ...
    });

Alternative: move the detect/summarise calls INSIDE the closure so
the variables are in scope naturally. Either is a one-line change.

Note: PHP arrow functions (`fn () =>`) capture automatically, but
`ComparisonService::evaluate()` uses a classic `function () use (...)`
closure — hence the explicit list is required.
