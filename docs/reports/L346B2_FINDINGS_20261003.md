# L346-B2 Findings — DataExportService silent empty arrays

**Date:** 2026-10-03
**Discovered by:** L346-B2 (Privacy services unit tests)
**Type:** Production bug (not fixed — L346-B2 scope is tests)
**Severity:** MEDIUM (Art. 38 portability — user data missing)

## Bug

`app/Services/Privacy/DataExportService.php::build()` calls
`safeQuery('needs', $userId)` and `safeQuery('offers', $userId)`:

    'needs'    => $this->safeQuery('needs', $user->id),
    'offers'   => $this->safeQuery('offers', $user->id),
    'consents' => $this->safeQuery('consent_logs', $user->id),

`safeQuery()` filters by `user_id`:

    DB::table($table)->where('user_id', $userId)->limit(1000)->get()

But the actual schema columns are different:

| Table | Real column | safeQuery uses |
|-------|-------------|----------------|
| `needs` | `requester_id` | `user_id` ❌ |
| `offers` | `provider_id` | `user_id` ❌ |
| `consent_logs` | `user_id` | `user_id` ✅ |

The `try/catch` in `safeQuery()` swallows the `QueryException`
(column not found) and returns `[]`.

## Impact

- `build()['needs']` is **always `[]`** — Art. 38 portability broken
- `build()['offers']` is **always `[]`** — Art. 38 portability broken
- `build()['consents']` works correctly (only one with matching column)
- Users requesting a data export receive an incomplete payload
- Silent failure: no error, no log, no 5xx

**Compliance:** Proclamation 1321/2024 Art. 38 (right to data
portability) is partially unmet — the export omits the user's own
needs and offers.

## Evidence

- Test `DataExportServiceTest::test_needs_returns_empty_due_to_schema_mismatch`
  asserts `build()['needs'] === []` with a valid user that has needs.
- Test `DataExportServiceTest::test_offers_returns_empty_due_to_schema_mismatch`
  asserts `build()['offers'] === []` with a valid user that has offers.
- Test `DataExportServiceTest::test_consents_included_when_present`
  confirms `consents` path works — proving the root cause is
  column-name mismatch, not a broader failure.

## Recommended fix (NOT applied — out of L346-B2 scope)

Option A — column-map in safeQuery:

    private const USER_COLUMN = [
        'needs'        => 'requester_id',
        'offers'       => 'provider_id',
        'consent_logs' => 'user_id',
    ];

    private function safeQuery(string $table, string $userId): array
    {
        try {
            $column = self::USER_COLUMN[$table] ?? 'user_id';
            return DB::table($table)
                ->where($column, $userId)
                ->limit(1000)
                ->get()
                ->map(fn($row) => (array) $row)
                ->toArray();
        } catch (\Throwable $e) {
            return [];
        }
    }

Option B — pass the column explicitly at each call site:

    'needs'    => $this->safeQuery('needs',    $user->id, 'requester_id'),
    'offers'   => $this->safeQuery('offers',   $user->id, 'provider_id'),
    'consents' => $this->safeQuery('consent_logs', $user->id, 'user_id'),

Option A is preferred (single source of truth for the mapping).

Optional hardening: replace `catch (\Throwable)` with a log on failure
so future schema drifts are visible instead of silent.

## L347-A Status: ✅ FIXED (2026-10-03)

**Fixed in commit:** `8268307` (L347-A)

**Fix:** `DataExportService::safeQuery()` now uses a per-table column
map (`USER_COLUMN` constant):
- `needs` → `requester_id`
- `offers` → `provider_id`
- `consent_logs` → `user_id`

Art. 38 portability now returns the user's own needs and offers.

**Verified by:**
- `DataExportServiceTest::test_needs_returns_users_own_needs` (new)
- `DataExportServiceTest::test_offers_returns_users_own_offers` (new)
